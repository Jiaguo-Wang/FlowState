## 任务 1：C K=5 反事实双零集合 — **成立**

只读计算集合 `{C_A_P04096, C_B_P05120, C_C_P06144, C_D_P07168, C_JOIN_P04096}`：

| 检查项 | 结果 |
| --- | --- |
| 候选合法性 | 5 个 ID 全部在冻结候选域内，`state_status=PROPOSED` |
| 总 Slot 消耗 | 5（每个 `expected_independent_slot_cost=1`），恰好等于 K=5，未超预算 |
| Current-Pending J | **0.000000**（A/B/C/D 四叶全部 E=T、G=0，`EXACT_ZERO_BY_DEFINITION`） |
| Frozen-Future J | **0.000000**（JOIN E=4096、G=0，`EXACT_ZERO_BY_DEFINITION`） |

**结论：双零集合在 K=5 下存在。** 原报告的"当前/未来权衡"（FS：Jcur 0 / Jfut 154.35）**不是 K=5 下不可避免的容量冲突，而是当前目标零边际提前停机的结果**——JOIN_P04096 对当前四个 Pending 的边际为 0（其 `token_compatible_calls=['C_JOIN']`），生产 Greedy 在第 4 次选择后全部边际归零即停机，不会为未来目标消耗第 5 个槽位。此集合仅为反事实分析，不作为修改后的生产 FlowState 输出；且 5 个入选状态的父状态均不在集合内（按冻结合同须安全释放），其 GPU 物化语义（是否需祖先驻留）未验证。

## 任务 2：动态边际 Greedy 的独立价值 — **在 C 上有真实且量化的改进**

按冻结 StandaloneTopK 定义（empty-set 独立收益降序、id 升序兜底、正收益过滤，取前 K），同一恢复估值、同一候选、同一预算：

| K | StandaloneTopK 选择 | J | Greedy 选择 | J | 差（Standalone−Greedy） |
| --- | --- | --- | --- | --- | --- |
| 3 | D_P07168, D_P07104, C_P06144 | 348.2340 | D_P07168, C_P06144, B_P05120 | 154.3490 | **+193.8851** |
| 5 | D_P07168, D_P07104, C_P06144, C_P06080, CD_P03072 | 348.2340 | D/C/B/A 四叶（4/5 槽） | 0.0000 | **+348.2340** |

机理（standalone 收益前几名）：D_P07168=274.0959、**D_P07104=271.5809**、C_P06144=233.8007、**C_P06080=231.3073**、CD_P03072=231.0898……同一 Pending 的"末端+距 64 Token 祖先"独立收益几乎相同，静态排序把两个近重复状态同时排进前列，挤掉 B/A；K=5 加码后仍然只覆盖 D/C，**J 纹丝不动**。Greedy 的边际更新在选中 D_P07168 后看到 D_P07104 的边际仅约 2.5（只补 64 Token 缺口），转而覆盖下一个 Pending。旁证：StandaloneTopK 的 K=3 集合与 Marconi C K=3 完全相同（位置代理同受近重复对误导，J 同为 348.2340）。

**结论：两者不持平——边际更新带来的改进是真实的**（K=3 +193.89、K=5 +348.23 模型 ms），且 Greedy 附带省 1 个槽位（K=5：4/5）。未修改任何工作负载。

## 任务 3：未来候选的决策时合法性 — **逻辑可选择 ≠ 决策时可用 ≠ GPU 待认证**

冻结证据（三结构一致）：

| 层级 | 判定 | 证据 |
| --- | --- | --- |
| 逻辑可选择 | **全部 48 个候选**（A20/B12/C16） | 冻结图内声明，含 B 的 S1、C 的 JOIN |
| 决策时可用（作为声明输入） | 是——访问事件/STE/位置代理均为协议预先声明 | `synthetic_access_events` 全部 `event_type=DECLARED_SYNTHETIC_ACCESS` |
| 决策时可用（作为已存在的可保留状态） | **否——零个候选** | 全部候选 `runtime_materialized=False`、`runtime_handle=null`；`runtime_actual_candidates=[]`；全部调用 `runtime_received=False`；全部访问事件 `runtime_observed=False` |
| GPU 待认证 | **全部 48 个候选** | 无任何物理物化依据；`planned_warmup` 只是两轮（WARM_0/WARM_1）带 token 的计划，从未执行 |

要点：
1. **Allocation Epoch 前没有任何状态被实际产生**。协议确实明确声明了两轮预热及其顺序（`planned_warmup`：B 为 2 轮×3 工作流、C 为 C_WARM_0/C_WARM_1，覆盖含 JOIN/S1 在内的全部调用），但均为计划，未运行。
2. **LRU 的访问事件不是决策前已发生的事件**：C 中 JOIN 的合成事件排在声明序列最末（`event_order` 30/31，为最大值），LRU 据此把从未执行的 JOIN 状态排为"最近访问"并首选保留——其 C K=3 选择 `{JOIN_P04096, JOIN_P04032, D_P07168}` 与该事件序完全吻合。所有事件 `runtime_observed=False`。
3. **对既有 CPU 对比有效性的影响**：Current-J 列仍为良定义的逻辑估值对比（"给定候选域，哪个子集最小化当前 J"），排名有效；但 **Frozen-Future J 列必须降格解读**——LRU/Marconi/KVFlow"保留 JOIN/S1"的前提是这些状态在决策时已存在，而它们只存在于计划中，不能当作当前可保留的 Recurrent Checkpoint。要实现这些选择需（a）投机预物化（计算成本未建模，`logical_cost=1` 只计槽位）或（b）状态出现时重规划（届时 FlowState 亦会重新决策，静态对比不再适用）。因此 0 胜/8 平/16 负的未来口径记录是**固定选集静态评分**，不是"LRU/Marconi 是更好在线策略"的证据；原报告"结构性口径差异"的判断成立且现有具体证据。

## 四个决策问题的回答

| 问题 | 回答 |
| --- | --- |
| 1. C K=5 的双零集合是否成立？ | **成立**（Jcur=0、Jfut=0、5/5 槽）；原权衡是零边际提前停机所致，非容量冲突 |
| 2. C K=3/5 的 Greedy 是否优于 StandaloneTopK？ | **是**（+193.89 / +348.23 模型 ms，且 K=5 少用 1 槽）；边际更新价值真实，源于避免近重复祖先对的静态冗余 |
