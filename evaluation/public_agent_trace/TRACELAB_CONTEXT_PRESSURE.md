# TraceLab 上下文覆盖与状态压力审计

## 技术摘要

64K profiler 扩展价值为 YES，128K 扩展价值为 YES；candidate-relative budget 的结构代表性为 NO。核心风险是 N 会随历史 checkpoint 数累积，而当前 demand 由 distinct exact parents X 决定。

本审计没有运行任何 checkpoint policy、Phi 或 GPU。所有快照只来自同 provider 内真实观测 overlap；完整 run 最大 context 只用于离线累计 cohort 与确定性采样分层，不进入 online anchor、pending 或 checkpoint value。

四个 cohort 均只包含严格闭合 Agent Runs。每个非空 `scale × provider × context bucket` 层固定选择一个 SHA-256 键最小的多轮 tool-call 时点；空层不补造。

## 诊断与下一步边界

- 64K profiler extension value: **YES**。eligible runs 增加 +7432（232.541%），selected unique runs 增加 +19（190.000%）。
- 128K profiler extension value: **YES**。eligible runs 增加 +17260（162.401%），selected unique runs 增加 +35（120.690%）。
- Candidate-relative budget: **NO**。50% 与 75% 档位在绝大多数 snapshots 已足以容纳全部 X，N 受历史长度放大，弱化了当前 pending state pressure。
- Pending-relative budget: **WEAK**。P 能描述当前 known demand，但 TraceLab 没有 LLM-level branching，本样本中非零 P 与 X 完全相同，无法验证共享 exact parent 时的去重语义；P=0 时公式仍因下限产生 K=1。
- Exact-parent-relative budget: **YES**。X 直接度量保护当前 pending 所需的 distinct exact-parent 状态，不会被历史 checkpoint 数量放大。
- TraceLab policy suitability: **WEAK**。真实 overlap、线性 history 与 exact parents 足以形成结构比较；但缺少显式 DAG、token IDs 和 runtime residency truth。

推荐下一步：先基于本审计结果单独冻结 demand-relative budget protocol；仅在独立 profiler 扩展后才把超过其有效域的 cohort 纳入 Phi-based comparison。

限制：TraceLab 没有显式 LLM-level DAG、token IDs 或 runtime residency truth；KVFlow 的 `steps_to_execution` 仍固定为 1。当前结果是结构审计，不是 policy comparison 或 runtime latency 结果。
