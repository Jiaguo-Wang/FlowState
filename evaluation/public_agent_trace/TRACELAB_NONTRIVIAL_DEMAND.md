# TraceLab C128 非平凡需求快照审计

## 技术摘要

C128 共形成 40,849 个合法、真实重叠的候选快照事件，其中 X>=2 的比例为 41.715%。当前冻结的 57 个正式快照中只有 22 个 X>=2 快照，其占比低于 C128 全量事件，因此在扩展 profiler 之前应先重新冻结需求感知采样；本步骤没有执行任何 policy、Phi 或 GPU。

候选快照事件定义为：C128 严格闭合且至少两轮的 Agent Run 中，每个包含已发出 tool call 的 round，以该 round 最后一个已发出 tool call 的时间为观测时点。活跃 workflows 只来自同 provider 的真实 run 区间重叠，且 W>=2；没有人工时间平移或合成并发。

## 当前 57 个快照为何三个受限 ratio 得到相同 K<X

当前 exact X histogram 为：X=1:35, X=2:13, X=3:2, X=4:1, X=5:1, X=6:5, X>6:0。对任意整数 X>=2，`max(1,floor(0.25X))`、`max(1,floor(0.50X))` 和 `max(1,floor(0.75X))` 都严格小于 X；对 X=1，三者都等于 X。因此三档的 K<X 条件都恰好等价于 X>=2，即 22/57=38.596%。

## 结构判断与下一步

- X>=2 是否充足：**YES**。全量 17,040 个事件，max20 投影 185 个快照、442 个 unique runs。
- X>=4 是否充足：**WEAK**。全量 419 个事件，max20 投影 38 个快照；实际 X>=4 值域包含 4 个 X 档。
- 当前样本是否低估非平凡需求：**YES**。当前样本 X>=2=38.596%，全量 C128=41.715%。
- 是否应在修改采样前先扩展 profiler：**NO**。

推荐下一步：**在 C128 内重新冻结 X>=2 sampling**。本步骤不执行该建议。

限制：这些结论证明结构样本量与多级 budget 可用性，不构成具体 policy effect 的统计功效分析。TraceLab 仍没有显式 LLM-level DAG、token IDs 或 runtime residency truth。
