# 四 Pending 整体性能归因审计（c_formal_perf_gpu，只读重聚合）

数据：60 个正式测量臂（门禁 2 臂不参与）；口径：每轮每策略四 Pending 等权
`x̄ = (1/4)Σ_p x_p`（TTFT 与 CUDA Prefill 同法），配对差为**同轮等权均值之差**。
这是"固定需求集合的等权独立请求性能"，**不是**连续 Workflow E2E、并发完成时间或生产 Goodput——
四次独立恢复的耗时不可相加冒充工作流执行时间。逐项数字见 `paper_pending_aggregate.csv`（103 行）。

## 四、机器双峰敏感性分析

规则沿用 final_report §5.1：`cuda_decode_ms > 150ms` 记慢模式（decode 中位 203 vs 121ms，prefill +15–20ms
传入 TTFT）。**主结果不剔除**；慢臂按策略合计 **FS 9 / SA 6 / WFC 2**（每轮分布见 §一表各单元格第三项
"TTFT/Prefill/慢臂数"；rep5 最重：FS 3 / SA 3 / WFC 0）。

- **方向性**：慢模式抽签不利于 FS（多抽 3–7 臂），而 FS 的整体优势仍在全部 5 轮成立——主结果对 FS
  是**保守**方向；
- 同轮 20 个配对的模式构成：FS−SA 双快 8 / 双慢 3 / **错配 9**；FS−WFC 9 / 0 / **11**。错配对中差值含
  ±15–20ms 的模式分量（不属策略）；C_C/C_D 的正中位（+6.6/+21.1）主要由错配驱动（逐轮符号随模式翻转）；
- **次要敏感性分析**（非主结果；规则：仅取各策略×Pending 格内 decode≤150ms 的臂，格中位再等权；
  每格 n=2–5 不等，已写入 CSV）：FS 68.5（格 n=[3,3,3,2]）vs SA 107.8（[4,3,4,3]）vs WFC 124.6（[5,4,4,5]）
  → FS−SA **−39.3**、FS−WFC **−56.1**。与全量口径（−34.1/−46.9）同向且更大，结论不变；
- 慢模式来源**未证实**（宿主级、时间相关、横跨三策略；推测涉及时钟/功耗状态，本轮无直接测量，不作断言）。

## 五、机制归因（区分：恢复前沿差异 / GPU 计算差异 / 未解释宿主变化）

1. **恢复前沿差异是整体收益的全部来源**。C_B：FS 保留本分支 E=5120（32 Token 续算）vs SA E=0
   （5152 Token 全量重算）→ Prefill 30.7 vs 192.8ms。C_A：FS 与 SA 的值模型都把 K=3 预算花在别处
   （E=0×2），WFC 固定 2048 前沿反而保留 → WFC 在该格最优。C_C/C_D：三策略中 FS/SA 前沿相同，
   **前沿差为零 ⇒ 不应期待稳定策略差**，实测差异即落入宿主噪声（§四）。
2. **GPU 计算差异完整解释等权优势**：等权 Prefill 差 ≈ 等权 TTFT 差（§二），窗口内非计算段三策略
   相等（4.7/5.0/5.1ms）。
3. **未解释宿主计时变化**：双峰模式（±15–20ms/臂 TTFT、decode ±80ms）+ queue/pregap ±1–2ms 抖动。
   已量化、已标注，不构成策略可归因差异。
4. **单请求收益与共享预算取舍**：K=3 在 16 个候选间零和。FS 的整体收益 = "把深恢复请求的分支留深"
   （C_B −163ms）减 "值模型让位时该到达完全冷启动"（C_A 相对 WFC +72ms）。固定需求集合上的净额
   为正；到达流中深恢复占比决定外推是否成立。

## 六、Control-inclusive 结论的证据边界

| 项 | 状态 | 数字 |
|---|---|---|
| 1. 请求级加速（直接实测） | ✅ 已测 | C_B 配对 −163.2ms（5/5 轮）；四 Pending 等权 −34.1（FS−SA）/−46.9（FS−WFC），5/5 轮 |
| 2. 控制分段耗时（直接实测） | ✅ 已测 | 认证+计划 ~160ms；协调+后检 ~870ms；窗口内必要控制 ≤5ms |
| 3. FS 相对 Baseline 的**增量**控制成本 | ✅ 已测≈0 | 生产核心三策略 1029 / 1028 / 1036ms——同一控制器不同选集，增量在噪声内 |
| 4. 多请求摊销（"约 7 次 C_B 型请求回本"） | ⚠️ **算术估算** | 1028/163.2≈6.3；非实测净收益 |
| 5. 完整在线 Control-inclusive E2E | ❌ **未测** | 连续 Workflow、apply 与请求重叠、并发 Goodput 均无测量 |

不得把第 4 项表述为实测净收益；第 5 项不存在任何测量支撑。

## 七、可写进 ICDE 正文 / 不可写的结论

**可写：**
1. 在固定四 Pending 需求集合上，FlowState 等权 TTFT 77.8ms vs StandaloneTopK 112.0ms vs WFC 125.2ms；
   同轮配对差 FS−SA −34.1ms [−42.3,−28.7]、FS−WFC −46.9ms [−55.3,−46.0]，五轮全负，且等权 CUDA Prefill
   差与 TTFT 差相等（优势源于恢复前沿驱动的计算节省）；
2. 收益呈分配依赖结构：深恢复请求（C_B，E=5120 vs 0）单格 −163.2ms（5.4×）；同前沿格请求成本不可区分；
   值模型让位格（C_A）落后固定前沿 WFC +71.7ms——这是 K=3 共享预算的显式取舍，非恢复机制缺陷；
3. 请求窗口内必要控制 ≤5ms 且三策略相等；每 Epoch 一次的生产核心控制 ~1.03s 且策略间增量≈0。

**不可写（过度结论）：**
- 任何"工作流/E2E/Goodput 加速"表述（本口径为独立请求等权，连续执行窗口未测）；
- 把"约 7 次请求回本"当实测净收益（摊销算术）；任何在线多请求摊销数字；
- 对机器双峰模式的成因断言（时钟/功耗未验证）；对 C_D "+21.1ms" 的策略归因（模式混入，快模式 +2.3）；
- 基于 n=5 的统计显著性声明；向其他到达流/工作负载的外推。

---

## 审计判定：**PARTIAL**

固定四 Pending 需求集合下 FlowState 的整体等权优势真实、五轮配对全负且方向对慢模式保守——总体收益
由配对测量支持；但判 PARTIAL，依据规约两条：(a) 相对 StandaloneTopK 的净优势**由单一深恢复请求类别
（C_B）支撑**，其余三格净贡献为正（不利 FS，其中 C_C/C_D 系机器双峰错配混入）；(b) 17/60 臂的宿主
双峰模式构成明显干扰（错配配对 9–11/20），虽不改变结论方向，但使同前沿格与 C_D 的策略间差不可归因。
本判定不等于生产端到端加速认证（在线 Control-inclusive E2E 未测）。
