# 补充边界与错误处理

- T0/T3/T4保留原定义。T5只代表本臂原后验、Cold/Oracle检查、重复报告格式化与附加记录完成，不含summary写盘、Engine清理、模型启动/历史重放，也不含跨臂离线复核和本报告统计。后者由verified_evidence_inventory.json记录独立起止时间，在所有GPU测量结束后执行；它们不是从在线路径移出的检查。
- 唯一移出T0–T4的是已有完整持久化副本的重复展示格式。完整原始响应的fsync、解码及真实性检查仍在发送Pending之前。此处任何失败都会阻止发送；服务端封装异常保持失败隔离。
- T4后重复展示文件写入若失败，已执行的请求无法撤销，整臂不得认证PASS、后续实验停止。这项后置展示错误与请求前必需的持久化错误需分开描述。本轮26个生命周期未发生此类错误，所有原始证据完整。
- process_time_ns记录进程CPU差，可能包含同期其他线程；它不是严格的单函数独占CPU时间。gpu_calls=0表示新增编码/展示函数没有GPU调用，不表示原同步哈希成本为零。
- 现有ABA/Generation边界没有被本轮补齐。安全等价仅依赖保留原全部状态操作/校验、同一连续Scheduler控制与独占受控Engine条件，不外推到任意并发Serving或长期状态租约。
