# 收尾门禁异常与最小修订

第一对批量臂完整实验PASS、宿主返回码0、Engine shutdown正常，但 execute.py 在收尾检查读到 GPU0 14 MiB、利用率4%，因新增的“退出后也必须0%”断言终止。原始 paired_launcher.log 与该臂所有文件保留，不覆盖。

本机 nvidia-smi --help-query-gpu 明确 utilization.gpu 是过去采样窗口中执行内核的时间比例，窗口在1秒至1/6秒之间。该读数不能独立证明当前仍有计算进程，更不能证明其他用户占用；其确切来源 UNKNOWN。随后只读复查目标卡14 MiB、0%、无计算进程、无实验容器残留，证据 resource_recovery_observation.json；不把当前复查冒称原失败瞬间已检查全部字段。

execute_v2.py 仅修正收尾门禁：仍要求显存<100MiB、无目标卡计算进程、无实验容器残留及磁盘>20GiB；启动前仍要求0%活动。与原P0实际资源合同一致，没有改任何控制/计时/正确性代码。四项CPU故障测试通过，活动进程或显存占用仍拒绝。execution_amendment.json 锁定新入口与首对原始摘要；原 execution_lock.json 不改。两已完成臂逐项复核后不重跑，负向首对保留；续接第二轮至第五轮。

首对批量−原版：控制+1374.954ms，完整+1925.759ms，为负向观测；此修订不改变任何性能结果，不能据其删掉首对或宣称已改善。
