# 计时口径及无法追溯的边界

冻结观测293.092856 ms没有frontier内部计时，不能唯一拆成历史子步骤；本轮72次profiling的对应均值299.434 ms必须作为独立测量报告。未按新测比例回填旧值。

冻结协调211.337401 ms可精确分解为：逐驱逐原语合计10.533572 ms、服务端其他工作26.936489 ms、服务端外173.867340 ms。服务端外包括客户端编码、连接、服务线程读取解码、队列/事件交接、响应和客户端状态整理，旧artifact不能进一步唯一拆分。

新profiling对每次RPC记录同一主机单调时钟，提交入口前、排队、服务端执行、事件交接、返回与客户端本地余量严格闭合，最大数值误差小于1e-12 ms。每个服务端子步骤同时记录包含和独占时间及调用次数；不能把二者混加。

公共阶段有一次句柄序列化和一次客户端候选状态转换；协调阶段各一次句柄序列化、状态转换和compact_census。compact_census使用已返回的view做CPU投影，不发新的census RPC。它们的联合耗时记录为client_local_ms，未单独逐函数计时，不为其编造独立分位数。

四次真实请求后的census属于原E2E请求验证部分，不属于本次三个控制段。其RPC原始计时也保存在profile.json的request_validation条目，优化没有改动该路径。

连接建立本身均值小于0.4ms；本轮没有把提交前残余武断解释成连接建立或GIL时间。连接复用、消息压缩等联合优化的效果以新216-run结果为准，本轮不提供未经单独消融测量的逐优化因果贡献。

所有统计值为各epoch累计后在72个epoch上的平均/P50/P95；P95不是单次底层操作的P95。TP=1，控制RPC跨worker和scheduler进程，rank间调用为零。没有新增GPU同步屏障；tensor.cpu/tolist的潜在设备等待包含在主机函数耗时中，不能当作单独GPU内核耗时。
